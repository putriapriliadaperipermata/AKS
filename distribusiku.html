Interpretasi

Aturan pembacaan laporan

  • Tingkat penyelesaian = jumlah pesanan selesai ÷ total pesanan × 100%.
  • Pesanan berisiko = status belum selesai dan estimasi tiba melewati batas waktu.
  • Ketepatan waktu dihitung dari pesanan selesai sebelum atau pada batas waktu.
  • Data demo ini disimpan pada browser lokal dan bukan data operasional sungguhan.
DOKUMENTASI LOGIKA

Aturan Sistem

Penjelasan keputusan sistem agar mudah dipresentasikan dan dikembangkan.

Alur bisnis utama

Input → Proses → Output sesuai materi studi kasus

1
Input pesanan

Admin memasukkan nama pelanggan, alamat/tujuan, barang, waktu batas, dan estimasi durasi.

2
Validasi data

Field wajib tidak boleh kosong; batas waktu harus valid; ID pesanan dibuat otomatis.

3
Penugasan kurir

Admin memilih kurir tersedia. Satu kurir pada demo ini dapat menangani beberapa pesanan, namun penugasan tetap harus mempertimbangkan kapasitas.

4
Perhitungan rute

Dijkstra mencari jalur terpendek antara titik pada graf dengan bobot jarak non-negatif. Ini bukan optimasi global untuk seluruh urutan multi-tujuan.

5
Pembaruan status

Admin memperbarui status dari Menunggu → Diproses → Dalam Perjalanan → Selesai. Status Ditunda dipakai jika ada kendala.

6
Deteksi keterlambatan

Untuk pesanan belum selesai, jika waktu sekarang melewati batas waktu, sistem memberi peringatan. Dalam demo, status berisiko juga dapat dihitung dari estimasi tiba yang melampaui batas.

7
Riwayat dan laporan

Setiap perubahan status dicatat dengan waktu, sehingga dapat ditelusuri dan diekspor ke CSV.

Kebutuhan fungsional

  • Kelola data pesanan, kurir, dan kendaraan.
  • Hitung dan tampilkan rute.
  • Lacak dan perbarui status.
  • Notifikasi serta laporan keterlambatan.

Kebutuhan non-fungsional

  • Antarmuka responsif untuk web/mobile.
  • Akses aman berbasis peran pengguna.
  • Riwayat tersimpan dan dapat diaudit.
  • Respons cepat dan mudah digunakan.
